Q3 payments incident — postmortem

The payments API returned 5xx errors for about 12 minutes on Sept 14, failing 3.2% of merchant requests. A stale pooled connection was handed to live requests after its idle timeout elapsed. Rolled back; resolved.

How the request flowed

Root cause

The pool checked idle timeout before the context deadline, so a connection that had just crossed the idle threshold was handed to an active request and rejected by the upstream. 

if conn.IdleTimeout < ctx.Deadline() {
  // pool returned a stale conn -> 5xx
  return ErrUpstream
}
The fix (one-line reorder) 
if ctx.Deadline() // check the deadline first
   && conn.IdleTimeout > remaining(ctx) {
  return pool.Drop(conn)
}
