How DNS resolution works

What happens between typing a name in the address bar and the first byte of the page.

The short version

Computers connect to IP addresses, not names. The Domain Name System (DNS) is the distributed phone book that turns a name such as example.com into an address such as 93.184.215.14. No single server knows every answer. Instead, a recursive resolver asks a chain of servers, each of which knows who to ask next.

The lookup, step by step

The resolver does the walking. Your laptop asks one question and waits.

  1. Your laptop checks its own cache. On a miss, it sends the question to the recursive resolver that the network gave it, usually run by your ISP or a public service such as 1.1.1.1.
  2. The resolver asks a root server. The root does not know the answer, but it knows which servers handle .com.
  3. The resolver asks a .com server. That server knows which name servers handle example.com.
  4. The resolver asks an example.com name server. This server is authoritative: it holds the real record and returns the address.

Caching and TTL

Every answer carries a time to live (TTL) in seconds. Until the TTL expires, the resolver answers from its cache and skips the walk. This is why a cold lookup can take 100 ms or more, but a warm lookup takes a few milliseconds.

It is also why a DNS change does not "propagate". Nothing is pushed. Each cache keeps the old answer until its copy expires, so lower the TTL a day before you plan to move a record.

Try it yourself

dig shows each step. The +trace flag makes it walk the tree itself instead of asking your resolver. 

$ dig +trace example.com
.                  518400  IN  NS   a.root-servers.net.
com.               172800  IN  NS   a.gtld-servers.net.
example.com.       172800  IN  NS   a.iana-servers.net.
example.com.       3600    IN  A    93.184.215.14
Why does the root not get every query on the internet?

Resolvers cache the root and TLD answers too, with TTLs of one to six days. A busy resolver asks the root about .com a few times a week, not once per lookup.

Common misconceptions

  • "DNS is one server." It is millions of servers, each responsible for one zone.
  • "Changes propagate." Caches expire. Nothing is pushed.
  • "Flushing my cache fixes it." Only your cache. The resolver keeps its own copy.
